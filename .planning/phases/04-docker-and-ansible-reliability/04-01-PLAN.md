<objective>
Add Docker container memory limits to prevent OOM cascades, make CV service deploys idempotent, and add a post-deploy smoke test for the CV service.

Purpose: Docker containers currently run with unlimited memory on a 2GB ARM64 instance. A single runaway container can OOM-kill everything. The CV Ansible role unconditionally restarts the service every run, causing brief downtime even when nothing changed. After deploy, there is no automated check that the CV service actually responds.

Output: Modified docker-compose.yml files with memory ceilings, and a modified deploy-cv Ansible role with idempotent restart + HTTP smoke test.

Note on DOCK-02: Image prune cron was explicitly dropped from this phase per user decision. Images are pre-built on Docker Hub and rarely updated, so dangling images do not accumulate in practice. DOCK-02 is deferred to v2.
</objective>

**Change 2: Add flush_handlers + smoke test (per D-07, D-08, D-09)**

Append the following tasks AFTER the "Enable and start CV service" task (at the very end of the file):

```yaml

- name: Flush handlers before smoke test
  meta: flush_handlers

- name: Smoke test CV service - Spanish
  ansible.builtin.uri:
    url: "http://127.0.0.1:8001/preview/es"
    method: GET
    status_code: 200
    timeout: 30
  register: cv_smoke_es
  until: cv_smoke_es.status == 200
  retries: 6
  delay: 5

- name: Smoke test CV service - English
  ansible.builtin.uri:
    url: "http://127.0.0.1:8001/preview/en"
    method: GET
    status_code: 200
    timeout: 30
  register: cv_smoke_en
  until: cv_smoke_en.status == 200
  retries: 6
  delay: 5

- name: Smoke test CV service - Catalan
  ansible.builtin.uri:
    url: "http://127.0.0.1:8001/preview/ca"
    method: GET
    status_code: 200
    timeout: 30
  register: cv_smoke_ca
  until: cv_smoke_ca.status == 200
  retries: 6
  delay: 5
```

Key details:
- `meta: flush_handlers` ensures any pending restart handler fires BEFORE the smoke test hits the service
- URLs use `127.0.0.1:8001` (loopback to CV service directly), NOT the public URL (avoids Anubis PoW challenge)
- `retries: 6` with `delay: 5` gives a 30-second budget for WeasyPrint cold start
- `timeout: 30` per request (WeasyPrint PDF gen can take 2-5s, 30s is conservative)
- DO NOT add `ignore_errors: true` to any smoke test task (per D-09 — failures must fail the play)
- `status_code: 200` makes the uri module fail on non-200 responses
- The `until` condition retries on connection refused (service starting up) or non-200 status
